--- [7] 调用方准入（S5-1）：默认档位 vs 白名单（同一进程、不重启 SA）---

================= 本轮结论（S7-1a）=================

【一句话】独立原生进程**能**拿到无障碍元素树，而且**带真实文本**：
`verdict=TREE-OK-WITH-TEXT`、`exit=0`、`connected=1 currentUserId=100`。

【证据链（全部是探针自己打印的真返回值）】
1. v1（普通客户端 `AccessibleAbilityClient`）：`RegisterAbilityListener` 之前直接调
   `GetWindows`/`GetRoot` → **ret=4004 = RET_ERR_NO_CONNECTION**；读码确认 4004 是
   `isConnected_` 未置真，而 `isConnected_` 只在 `Init(channel, channelId)` 里置真
   → **channel 只由系统下发给「登记过的无障碍 ability」**，普通进程拿不到。
2. v2（`AccessibilityUITestAbility`，即 uitest 用的那条原生口子）：
   `RegisterAbilityListener` → `Connect(0)` → `OnAbilityConnected` 回调（~500–600 ms）→
   可以 `GetWindows`/`GetRoot`/`GetChildren`。
3. 第一版 v2 直接跑 → `RegisterAbilityListener ret=1005 = RET_ERR_NO_PERMISSION`；
   读服务端代码：`Permission::CheckCallingPermission(OHOS_PERMISSION_ACCESSIBILITY_EXTENSION_ABILITY)`
   且 `processName != "hdcd"` → 拒。**权限对象是进程的 native token**。
4. 授途径（产品级、配置驱动）：init 服务 cfg 的 `permission` / `permission_acls` 字段
   （`init_service.c` 用它构造 `NativeTokenInfoParams` → `GetAccessTokenId` → 子进程
   `SetSelfTokenID`）。本轮给取证服务加了：
     permission: ACCESSIBILITY_EXTENSION_ABILITY + QUERY_ACCESSIBILITY_ELEMENT
     permission_acls: INJECT_INPUT_EVENT（留给 S7-3 执行侧）
   （本树先例：`base/sensors/start/etc/init/msdp_musl.cfg` 就是这么给 msdp 声明的。）
5. 加完权限后：`[13a]` 全窗口模式 `printed=169 withText=14 clickable=6`，
   读到的文本 = ["上滑解锁","21:25","2026年10月5日","星期一","丙午年八月廿五","没有 SIM 卡","100%"]
   （当前屏幕是锁屏）；`[13b]` 单窗口（winId=6）`printed=43 withText=7` 同样 exit=0。
   窗口列表：win6(type2110)/win3(2112)/win4(2111)/win10(2108)/win5(2001) 共 5 个。

【对 S7 的意义】
- **SA 里封 ReadScreen 可行**（不再有"必须先写 ArkTS 扩展"的结论）：SA 只要在自己的
  `lut_sa.cfg` 里声明同样两个权限，进程内的 token 就带着它们 → v2 这条路在 SA 进程内同样可用。
- 执行侧也齐了：同一个 API 面里有 `ExecuteAction(elementInfo, action)` / `InjectGesture` /
  `SetTargetBundleName`（目标范围可作为隐私/策略旋钮）。
- 已知边界（如实记录）：
  ① 走的是"UITest ability"模式（管理器把它登记成 `Utils::GetUri(processName, processName)` 的 ability），
     这是系统给原生进程的读屏口子，但**语义上是测试框架用的口子**；生产加固版应改为正式的无障碍扩展。
  ② 本轮是**只读**：探针不调用任何 ExecuteAction/InjectGesture，permission_acls 只是先声明。
  ③ 连接是进程级单例状态（`RET_ERR_CONNECTION_EXIST` 表示已连），与真实 uitest 运行会互斥。
